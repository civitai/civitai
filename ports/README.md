# Node → Go ports

Some read endpoints of the Node app (Next.js + tRPC, `src/`) are being ported to Go services
(`apps/feed-go`, `apps/beacon-go`). [`manifest.json`](manifest.json) is the one list of them: which
endpoint, which Go service and handler, which flags route it, and where it is in its lifecycle.
[`manifest.schema.json`](manifest.schema.json) is its schema.

## Using it

- **Does my change touch a port?** `node scripts/ports/touched.mjs <file>...`, or
  `node scripts/ports/touched.mjs --base origin/main` for your branch. It prints the ports and the
  changed files that tie each one in.
- **It does.** Read the port's entry. Change the Node entry and the Go handler (`goHandler`) in the
  same PR so both still answer the same, and update the Go service's golden fixtures where its
  README says so. The Go tests run in that service's own workflow.
- **A `@ported-to-go` comment** above a symbol in `src/` marks a port's Node entry. It is generated;
  do not edit or copy it.

## Fields

Hand-written: `id`, `kind` (`trpc` | `rest`), `service`, `status`, `routes`, `nodeEntry`
(`{ file, symbol }`; `symbol` is `default`, a top-level name, or `router.procedure`), `goHandler`,
`goRoots` (optional), `flags` (`shadow`, `transport`, `probe` Flipt keys, or null), `holdout`, `soak`.
The schema's `description`s say what each holds.

Generated by `node scripts/ports/generate.mjs`; never edit them by hand:

- `nodeDeps`: repo files the Node entry reaches through runtime imports, followed from the entry
  symbol (not its whole file) and then file by file. Type-only imports are skipped; a submodule
  counts as its path (its pin). These lists are wide: a feed endpoint reaches about 1,400 files,
  because the service layer imports widely, so many PRs touch the feed ports.
- `goDeps`: the service module's files in `go list -deps` of `goRoots` (default: the `goHandler`
  directories), listed for linux/amd64 without cgo, plus `goHandler`, `go.mod` and `go.sum`.

The generator also writes the `@ported-to-go` markers. After editing the manifest, or code that moves
an entry symbol or its imports, run it and commit what it changes. It parses source and runs
`go list`; it type-checks nothing, builds nothing and takes a few seconds. It needs `pnpm install`
(for `typescript` and `ajv`) and Go on `PATH`.

## Lifecycle

| `status`        | Who answers                                                    | What else is true                                                                                                    |
| --------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `shadow`        | Node, always                                                   | Go recomputes a sample of requests and compares (`flags.shadow`).                                                    |
| `ramp`          | Go for a share of users (`flags.transport`), Node for the rest | Comparison continues.                                                                                                |
| `soak`          | Go for everyone but a Node holdout cohort (`holdout`, percent) | The holdout keeps shadow-comparing; `soak.startedAt` is set. Lasts at least 14 days.                                 |
| `node-fallback` | Go                                                             | The Node handler stays only as the fallback for shapes Go does not handle: no traffic share, no comparisons.         |
| `go-only`       | Go                                                             | The Node path is deleted (`nodeEntry: null`). Only once Go's fallback rate is about zero and a human has signed off. |

**Soak exit gate** (soak → node-fallback), all of:

1. 14 days in soak;
2. match rate ≥ 0.995 in every comparison category;
3. no open mismatch class;
4. the CI differential suite green;
5. fallback rate < 0.1%;
6. the human sign-off recorded in the manifest (`soak.signedOffBy`, `soak.signedOffAt`).

The generator enforces only what the repo can see: the fields each status needs (for example
`soak` needs `holdout` and `soak.startedAt`; `node-fallback` and `go-only` need the sign-off) and
that `signedOffAt` is at least 14 days after `startedAt`. Items 2–5 are measured outside the repo
and checked by the person signing off.

**Live routing state.** The manifest records the stage a port is meant to be in; it does not read
flag values. To see what is routed right now, use the HQ routing-state tool `ports_state` (being
added).

## CI

`.github/workflows/ports.yml`:

- `manifest` runs the generator's tests and `node scripts/ports/generate.mjs --check`, which fails
  when the manifest breaks the schema or the lifecycle checks, when `nodeDeps` / `goDeps` differ from
  a fresh generation, or when a marker is missing, stale, on the wrong symbol, or on something that
  is not a port.
- `touched` maps the PR's changed files to ports. It never fails on a touched port. Its job outputs
  are `ids` (JSON array of port ids), `count`, and `touched` (the full result:
  `{ ports: [{ id, service, status, manifest, node, go }], ids, changedFiles }`, where `node` / `go`
  are the changed files that touch the port and `manifest` is true when its entry changed). A later
  job can read `needs.touched.outputs.ids` to choose which parity suites to run; that wiring is not
  in place yet.
