# Knights of New Order: gold conversion

Converting gold is now a purchase in the gold shop: a Buzz pack is a fixed `(gold, buzz)` conversion that reuses everything below. See [`knights-shop.md`](knights-shop.md).

Moved from `apps/knights/CLAUDE.md`. Code lives in `apps/knights/src/lib/server/conversion`.

Migrations `20261209120000_knights_new_order_player_and_link_review` (`NewOrderPlayer.goldPending` / `goldEarned` / `goldConverted`) and `20261210120000_knights_v2_tables` (`KnightsGoldConversion`), both applied by hand. Rate, minimum, retry age and the tick's retry bounds: `config.ts`. Deploy order on prod: apply the `NewOrderPlayer` migration, then the tables migration, then deploy the main app (its generated Prisma client reads the gold columns), then the Knights app, never earlier than the main app: until the main app's `resetPlayer` zeroes `goldEarned`, a reset through civitai.com leaves convertible gold.

- Recent purchases (`shop/inventory.ts`, `recentPurchases`): `/shop` lists the player's last 8 shop purchases (a Buzz pack's status follows its conversion). The old "convert everything" `listRecentConversions` and its Convert button are gone.
- Balances (`balance.ts`): pending (`goldPending`), convertible (`goldEarned - goldConverted`, the shop's spendable gold), frozen, on its way (reserved by an unconfirmed conversion or membership purchase), spent in the shop (cosmetics and membership) and converted (paid only). `goldConverted` is the one counter for gold that left the player's hands: conversions, Buzz packs and shop spending all add to it. Gold is convertible as soon as it is earned (a vote graded correct, a completed Watch). A held player (payout block set, or banned) has every unconverted gold frozen and none convertible; nothing is lost, and a released player's gold shows as convertible again. A held player keeps playing: their votes, rating and yes/no, are recorded, graded and earn XP, but are stored at weight 0 and so carry no weight in any verdict (`decideChoice`, `decideYesNo`), quorum or escalation; clearing the hold does not re-weight votes already cast. A career reset (`resetPlayer`) forfeits unconverted gold, as it does the old counters: pending goes to 0, earned drops to what was converted or reserved, and a reservation made before the reset that Buzz later refuses is forfeited rather than given back (the player is told). `resetPlayer` sets `startAt` from the database clock under the player row lock, and conversions are stamped on that clock, so the two are ordered by the lock.
- Label pass (`label-pass.ts`): `POST /api/jobs/tick` runs `runLabelPass` every tick within a time budget; it sets up the question rules only for a kind of vote that has labels waiting. Everything it writes is keyed on the data (unlabelled votes), so a pass cut short resumes on the next tick and a repeat writes nothing.
- Labels (`labels.ts`): one `knight` label per graded rating vote (`settledAt`) and per given yes/no answer (`createdAt`), for players not held and for votes that carried weight (a vote cast while held has weight 0 and is never labelled, even after the hold clears), written through `label_store.record_label` (shape: `docs/features/label-store.md`). `KnightsVote.labelled` marks done. A hidden check (negative `itemId`, a golden-set answer) is never labelled and never scanned. A held player's votes stay unlabelled because the store never retracts a label, and a vote cast while held stays so for good. A vote the store refused stays unlabelled and is retried once 10 minutes have passed since its last failure, up to 5 refusals; when every vote in a raising batch raises the store is taken to be down and nothing is recorded against the votes; a batch that raises is retried vote by vote so one vote cannot block the rest (`labelFailures` in the result; `label_store.record_failure` has the reason). The rating write-back (`setNsfwLevelKono`) does not wait for this.
- Converting (`convert.ts`; the only way to Buzz is a shop Buzz pack, which reserves the gold in the purchase transaction: a `pending` `KnightsGoldConversion` with its own `externalTransactionId`, and the gold added to `goldConverted`; `settleConversion` then asks Buzz (`buzz.ts`, through `@civitai/buzz`) outside the transaction with that key).
  - `paid`: the Buzz transaction id is stored and never overwritten; a 409 (key already paid) leaves it empty.
  - Unknown outcome (timeout, network, 5xx, 408, 429): the row stays `pending` with the gold reserved. The tick (`retryPendingConversions`: not held, bounded by count and time, skipped with a warning when `BUZZ_ENDPOINT` is unset), sends the same key. Retries take the least recently attempted first and skip rows tried within the retry age, so a stuck one cannot hold up the rest; none is started that could not finish inside the tick's budget. A Buzz pack is refused, and nothing reserved, while `BUZZ_ENDPOINT` is unset.
  - `failed`: any other 4xx. The reservation is released in the same transaction, the player sees a failure message and it is logged.
- Kill switch: conversion is on by default; `KNIGHTS_CONVERSION_DISABLED` (`conversionEnabled()` in `runtime.ts`) set to exactly `true` turns it off without a deploy (e.g. a farming incident or a Buzz outage). Off: Buzz packs are refused (403, nothing reserved) and the tick skips conversion retries, while the rest of the shop still sells (its own switch is `KNIGHTS_SHOP_DISABLED`, see the shop doc); gold still accrues and the label pass still writes labels.
- Logging goes through `src/lib/server/axiom.ts`, a forwarding file in the datastream ledger test. The label pass logs `knights-label-pass` with the Buzz converted per UTC day when it wrote or failed a label. Label loss is logged at error level too, with counts and the store's own player-hash prefix only, never a user id: `knights-label-failures` on every pass with refused or raised votes, `knights-label-given-up` once per vote given up on after 5 refusals (it is then marked `labelled` without a label), and `knights-label-pass-failed` when the pass itself raises. The tick's status and body are unchanged (a raising pass is a 500).
- Tests: `convert.pglite.test.ts` (and the shop's `shop/purchase.pglite.test.ts` for Buzz packs), `label-pass.pglite.test.ts` (boots the real label store migration via `bootLabelStore`).
